# 0.3.2-e：移除自有 30K 返回截断，输出交原生 agent runtime 兜底

> 2026-10-27 user 指令：① 0.3.2-d 已推 GitHub（master + tag `v0.3.2-d`）；② 下一轮 = **拿掉 30K 截断**——消费方全是原生 agent runtime（DSH 自带 spill/输出保护；Codex 等 foreign runtime 亦各有保护），我们不需要自造一层截断，让原生机制起作用即可，移植到任何 runtime 也同形。涉及工具：**remote**（oneshot + PTY）与 **hub execution**（oneshot + PTY）。

## 0. 设计（user 定稿）

**删的**（我们自有的「返回窗口」层）：
1. `tailWindow(text, cap, stats)`（nonce-framing.ts）及其 5 个调用点：driver.execute hub oneshot lane、dispatchPty、oneshot()、hubOneshot()、hub-tool exec pty。
2. `maxOutputChars` 配置（plugin.ts RemoteRowConfig + zod default 30_000 + driver opts）——配置的就是这层截断，随层一并退役。
3. 对端 `runOneShotExec` 的 `EXEC_TAIL_WINDOW`（exec.ts:49/140）——hub-tool exec oneshot 的 30K 在对端这里剪。

**保留的**（内存安全 + 诚实披露，不是返回窗口）：
- ring 留存上限：native/PTY 4,000,000 UTF-16 单位（Utf16TailRing）、hub oneshot 4MiB bytes（ByteTailRing）——防 OOM 的 retention，超出后保留尾部。
- `outputStats`（total/retained/dropped/returned/retentionLimit）照旧；
- retention eviction（>4M 才发生）仍有一行 banner 披露（新 helper `disclose`，仅 dropped>0 时打头），`truncated` 字段语义收敛为「retention 掐掉的原始总量」；hub 同步对端无 stats 的 lossy 尾披露不变。
- renderValue 的 truncated 标记行不变。

**返回形状变化**：≤留存上限的输出**全量内联返回**（35K 案例从「30K 尾窗 + banner」变为「35000 全量 + stats returned=35000」）；>4M 时返回 retained 尾 + banner + stats。模型上下文保护交给 DSH 原生 spill-policy（约 50K 字符阈值起 spill）或 foreign runtime 各自机制——**我们不做 tool-side spill，也不抬上限去凑原生阈值**。
