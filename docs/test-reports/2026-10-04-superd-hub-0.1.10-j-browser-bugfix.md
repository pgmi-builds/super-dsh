## 范围与判据

用户指令：先保存 h 阶段现场，再修复 h 报告遗留。h snapshot = `f3d94ef`。新版本只经 tarball，未发布。

主验收判据按用户补充调整：在本版本新建会话并真实回复 → 切去 Native/其它 agent world → 回来重放刚才的 transcript → 真实续聊。旧版本会话仅作兼容性观察，不因旧 preset/provider/model 缺失把本版本主路径判失败。

## 根因

- F1：共享 world composition 将 `file-upload` 误判为纯 client row 而禁用；它实际提供上游 SessionController 必需的 `fileUploads` Host service。修复在自有 patch 层保留该 row，世界依然无 client runner/监听端口。
- F2：`session/control` 终态失败会结束页面唯一 RemoteSnapshotStream consumer；之后 `restart();start()` 不重新消费。h 页面先切 Codex 失败再切 Claude 时，选模型成功但芯片不更新；完整刷新后只切 Claude，同样操作即时更新。无需对四个业务 adapter 加额外投影。先消除 F1 触发源，再从新页面走完整切换链验证。框架级故障恢复作为独立讨论项。
- F3：Hermes 的 `titleSourceSeq ??= session.append(user/message).seq` 短路了第二条及后续用户消息写入；持久 assistant 出现而 UI pending user echo 排到末尾，重开后 echo 消失。改为无条件 append，再只保留首 seq。已缺失的历史 user 不作补造。
- Codex 现场条件：PC 原生 auth 为 ChatGPT 模式；测试 home 有第三方 key，Codex store 原条目是 env 引用。rig 新增显式 seeder，把测试 key 写入 adapter 自有0600 store，依既有 child synthetic env_key 机制消费，不改原生 config/auth。
- F4（i 实测新发现）：新建 Codex 会话选 deepseek-flash，芯片正确，但请求报服务端只支持 DeepSeek model、实际传了 gpt-6.1-sol。`#applyRoute` 冷启动分支只钉 provider，跳过 setModel；首次 thread/start 和 turn/start 继承 client 原生默认。修复为在 ensureStarted 前钉当前 route model。回归使用生产 CodexAgent + 实际 app-server transport/fake 子进程，直接检查首 thread/turn 的 wire 参数；旧实现 RED（native default），新实现 GREEN 5/5。
