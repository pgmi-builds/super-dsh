## 内容（两独立修复，均已 user 亲手验收）

### 1. Hub 侧栏选择器两缺陷（super-dsh，commit 35bc3fa）

- **全新安装后 Hub 行出现但选择器不渲染，直到重启**：fusion 旗标/transport 脚本/roster 种子均烘在**所服务 index**（webserver/index-inject，每次 serve 现取），而 client-hmr 把热加载的 client half 直接应用于已 boot 页面——安装前 boot 的页面永远读不到旗标。transport 按设计必须先于 app boot（上传钩子构造期读取），故诚实修复 = 页面自愈重载一次：fusion 行发布 `fusionTransportArmed()`（ctx.effect 计数），roster GET 增量携带 `hub.fusion`，client entry 在旗标缺席时探测一次，armed 即 `sessionStorage` 标记 + `location.reload()`（标记防循环；`false`/缺席 = T-E flag-off 或旧 host，不重载）。
- **iOS Safari 侧栏滚动后选择器错位**：选择器 pill 原为 `position: fixed` 锚定实测行盒（仅挂载/行 resize/窗口 resize 重测），滚动移动行而不触发任何重测。改为 `position: absolute` 锚定 Menu wrapper span（上游 `.root` 本就 `position: relative` 且在行内随流），经新纯模块 `pill-geometry.ts` 取 wrapper 相对偏移——偏移按构造滚动不变，零 JS 随滚，打开的菜单经原生 Menu 自身 capture-scroll 锚定跟随。pill 保持在 wrapper 子树内，上游键盘 refocus 契约不动。

### 2. Mobile Responsive 触摸优先门控（better-dsh，本轮）

user 观察：桌面 web 缩窗或呼出右侧栏后左侧栏被压到零宽不可见，toggle 随之消失，仅剩非原生的鼠标拖拽呼出。根因两层：上游 AppFrame 以 **frame 自身盒宽**（右栏 grid track 计入）<1024 自动收敛为 56px 轨（原生带 toggle）；本模块在此之上**无条件**把该轨压到零宽，且 2026-09-11 波段让鼠标输入在面板窄态也可滑动手势——桌面端「隐形侧栏 + 无 toggle + 不可发现的拖拽」，最终只能 reload。

修复（user 裁决方向：按触摸界面而非纯屏宽判定）：整套 mobile surface（零宽 CSS + 手势）仅在 **touch-first** 设备挂载——`(hover: none) and (pointer: coarse)`（主输入指针习惯用法；`maxTouchPoints` 降级仅在 matchMedia 完全不可用时使用，避免触摸屏笔记本误入）。桌面端从此不挂载任何 mobile 面：上游原生窄态（rail + 可见 toggle）即桌面行为；鼠标滑动手势随 2026-09-11 波段一并废止（2026-10-18 user 裁决取代）。指针硬件变化（tablet 接驳）经 media query `change` 实时重评估。手机/平板行为逐字节不变。
