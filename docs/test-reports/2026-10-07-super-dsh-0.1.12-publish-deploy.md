# Super D 0.1.12: web-trust alignment and production deployment

2026-10-07. The user explicitly authorized publishing 0.1.12, installing it on PC and dev3, removing superseded trust configuration and restarting both production dsh services. This authorization applies to this release only.

## Source and delivery contract

Compared against dashr physical latest `fe3c99a` (the remote and registry D release are older). The authentication-only connection helper is byte-identical; server admission and all-host client script use the same native extension points. Super D retains its own component names and its legacy comma/whitespace authority parser. The shipped composite now enables `trustAllHosts: true`; the testing launcher no longer adds an enabling override.

No host/trusted-host CLI flags or trust-specific environment are required. Native `connection.requestRejection` delegates to native cookie authorization without Host/Origin fences. The head script establishes `__DSH_TRANSPORT__.ownsHost` before application boot, so native client loopback/trust checks recognize the serving authority. Anonymous, invalid, expired and wrong-authority cookies remain rejected. Existing authentication and unrelated runtime environment remain in place.

Actual TypeScript LSP definitions/references and TypeScript AST traversal traced the native admission, index authorization and client isLoopback surface. Native-connection bundle regression was red before the default change and green after it. Independent read-only review found no critical/important blockers; its 13 targeted tests passed.
