## 发布过程记录

1. **`--tag latest` 裁决依据**：`0.3.2-d` 语义上是 prerelease（字母后缀），npm 强制显式 tag。按总纲 1d「registry `latest` 保持最近一次获准发布」，本轮即最近获准发布 → `latest`。区间依赖（`^0.3.2`）按 semver 永不匹配 prerelease，无意外升级面；Super 的 companion 解析先 exact `better-dsh@0.3.2-d`，不依赖 tag。dist-tag 可事后移动（版本本身不可变）。
2. **发布顺序**：better-dsh 先（Super 运行时 exact 回退链需要它在库）；super-dsh 后。
3. **凭据纪律**：token（`~/workspaces/base/secrets/npm.env` → `NPM_ACCESS_TOKEN`）写 0600 临时 npmrc，`NPM_CONFIG_USERCONFIG` 指向，每段结束即删；token 不进仓库/长期 npmrc/报告。
4. **registry 收敛**：publish 回执 `+` 即时返回，元数据可见性延迟为 npm 常态——better-dsh 约 1 分钟收敛；super-dsh（21MB）更慢（本记录补充实测收敛时间于文末）。等待期间**未重发**（版本不可变天然防重）。
