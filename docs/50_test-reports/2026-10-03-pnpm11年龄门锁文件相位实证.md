# pnpm 11 年龄门：`minimumReleaseAgeExclude` 对"锁文件校验相位"完全无效（2026-10-03 实证）

- **触发**：user 在 homepc（prod）执行 `dsh plugin --profile web add better-dsh@0.2.5-b`，被拦：
  ```
  ✗ Lockfile failed supply-chain policy check (431 entries in 2.6s)
  [ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION] 1 lockfile entries failed verification:
    super-dsh@0.1.9 was published at 2026-10-02T07:45:36.963Z, within the minimumReleaseAge cutoff
  ```
  即：**装 better-dsh 被 _另一个插件_ super-dsh@0.1.9 的年龄拦下**（该条目在 profile 锁文件里，发布未满 24h）。
- **环境**：pnpm 11.7.0，profile `~/.dsh/profiles/web`，core dsh 0.2.0-rc.2。

## 一、决定性 A/B（同一份 prod 锁文件，只改变量）

把 prod profile 的 `package.json` + `pnpm-lock.yaml` + `pnpm-workspace.yaml` 复制到 `.scratch/age-probe/`，
每个变体只往 `pnpm-workspace.yaml` 追加一行，跑 `pnpm install --lockfile-only`，只看策略结论行：

| 变体 | `minimumReleaseAgeExclude` 内容 | 结果 |
|---|---|---|
| **V1** 现状 | `better-dsh` + `super-dsh@0.1.5-a` + `super-dsh@0.1.9` | ✗ failed（复现现场报错） |
| **V2** | V1 + 裸名 `super-dsh` | ✗ failed |
| **V3** | V2 + 裸名 `better-dsh` | ✗ failed |
| **V4** | V1 + `minimumReleaseAge: 0` | **✓ passes** |

**结论**：在 pnpm 11.7.0 上，`minimumReleaseAgeExclude` —— 无论 `pkg@x.y.z` 形式还是裸包名 ——
**都不能豁免锁文件校验相位**；唯一有效旋钮是 `minimumReleaseAge` 本身（设 0，或设成小于该条目年龄的值）。
本仓 AGENTS.md 此前"持久形式 = 裸包名，全相位生效（scratch A5–A7 实证）"的结论**是错的，已订正**。

## 二、修复（prod 现场）

```yaml
# ~/.dsh/profiles/web/pnpm-workspace.yaml  （追加）
minimumReleaseAge: 0
```

- 备份：`pnpm-workspace.yaml.bak-minimumReleaseAge-20261003`。
- 重跑 user 原命令：`Packages: +8 -95`，`Done in 4.8s`，pin 落到 `0.2.5-b`。
- 装机核查：`version 0.2.5-b` / `deps: None, optional: None` / `lib/kernel-bridge.py` 在位 /
  树里无 `zeromq` / lockfile integrity `sha512-M93FoCq…BYYrHQ==`（与 registry 发布物、与 dev3 拉到的**同一份**）。

## 三、影响面与建议

- **任何"发布后立刻装"的 profile 都会撞这道门**，而且拦的往往是**别的**插件条目（本例是 super-dsh）。
  当前 prod profile 的 `minimumReleaseAgeExclude` 三条全是无效配置（留着无害，但别再依赖它）。
- 两条可行路线：① profile 级 `minimumReleaseAge: 0`（本次采用，最省事，代价是该 profile 放弃 24h 冷却）；
  ② 等服务窗口（super-dsh@0.1.9 → 2026-10-03T07:45Z / 15:45 HKT 自然解锁）——但装完 better-dsh@0.2.5-b 后，
  它自己又变成"未满 24h 条目"，后续任何 pnpm 操作会**再撞一次**，所以路线 ② 只是把窗口推后。
- `dsh plugin add` 输出里的 `dshmarket@1.40.0 is incompatible with dsh 0.2.0-rc.2`（peer 不符）是**既有**状态
  （untouched 分支：保留安装、启动时 deny，需 `dsh plugin allow-version` 豁免），与本次改动无关。
